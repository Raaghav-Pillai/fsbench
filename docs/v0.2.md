# FSBench v0.2

FSBench evaluates models, retrieval interfaces, and controlled filesystem conditions separately. Correctness, evidence retrieval, cost, and latency remain separate outcomes; there is no combined score. The [project blog](https://raaghav-pillai.github.io/benchmarks/fsbench/) explains the motivation.

## 1. Controlled tool policies

| Policy | Toolset | Behavior |
|---|---|---|
| `naturalistic` | any | The model chooses among all tools. |
| `require_index` | indexed | Full interface, with an explicit requirement to successfully call `search_index` before answering. |
| `index_first` | indexed | Only `search_index` is initially exposed; a successful search unlocks all file tools. |
| `files_only` | files | Explicit file-interface restriction. |
| `shell_only` | shell | Explicit shell-interface restriction. |

Policy checks run inside the tool boundary as well as in evaluation. Unsupported combinations are rejected before execution. A failed search does not unlock tools; a successful zero-result search does. No search is fabricated on the agent's behalf. Missing required tool use sets `valid=false`, `success=false`, and `failure_type=required_tool_not_used`; `answer_correct` and `score` still describe task correctness. `required_tool_used` is vacuously true when there are no required tools.

Metadata records `tool_policy`, `policy_version`, `required_tools`, `tools_used`, and usage counts. Metrics include `first_tool_used` and zero-based `steps_before_required_tool` (null when no required call occurs). Counts include unsuccessful attempts; policy satisfaction requires a successful call.

The controlled filename-noise experiment uses the existing 80 environments, one model, and three explicit arms:

```powershell
fsbench validate --envs envs/exp_noise_v2 --filename-noise --index
fsbench run --envs envs/exp_noise_v2 --model openai/gpt-4o-mini `
  --arm files:naturalistic --arm indexed:naturalistic --arm indexed:index_first `
  --max-steps 40 --temperature 0 --order-seed 7 `
  --experiment filename_noise_tool_policies_v1 --out runs/exp_noise_policies_v1
fsbench evaluate --runs runs/exp_noise_policies_v1 --paired --interaction `
  --out runs/exp_noise_policies_v1/results.csv
fsbench plot --runs runs/exp_noise_policies_v1 --paired --x filename_noise `
  --out runs/exp_noise_policies_v1/plots
```

Naturalistic prompting remains unchanged. `index_first` changes both the instruction and initial tool availability, so this estimates the effect of an enforced index-first strategy, not a prompt-independent causal effect of the BM25 algorithm alone. The index uses visible document names and extracted content, never relevance labels or the hidden manifest.

## 2. Difficulty composition

Profiles combine existing parameters; no new entropy variable was added.

| Profile | Settings beyond defaults |
|---|---|
| clean | depth 0; filename noise, distractors, optional stale versions, semantic similarity all 0 |
| navigation_stress | depth 10; filename noise .8; 100 distractors |
| ambiguity_stress | filename noise .8; 100 distractors; similarity .9; optional stale rate .5; duplicate rate .3 |
| max_stress | depth 10; filename noise .9; directory noise .8; scatter .8; 300 distractors; similarity .9; duplicates .5; optional stale rate 1; all seven formats |

Ambiguity stress includes distractors so similarity has something to act on. Task-inherent traps remain present even when the optional stale rate is zero; a clean conflict task still tests source authority. Changes to distractor count, duplication, stale rate, and MIME diversity intentionally change inventory or rendered bytes. The task, facts, answer, required document IDs, and shared document identities stay fixed. Byte-for-byte invariance applies to a filename-only intervention, not a MIME intervention.

```powershell
fsbench sweep --task conflict --profiles clean navigation_stress ambiguity_stress max_stress `
  --replicates 20 --seed-offset 1 --out envs/stress_v1
fsbench validate --envs envs/stress_v1 --composed --index
fsbench sweep --task conflict --profile clean --set distractors=50 `
  --vary filename_noise=0,0.9 --vary stale_version_rate=0,0.5 `
  --replicates 20 --seed-offset 1 --out envs/noise_stale_v1
```

Repeated `--vary` now defaults to a full Cartesian product. Use `--ofat` to retain one-factor-at-a-time generation; `--grid` is still accepted. `--profile` aliases `--preset`; `--set` overrides profile values. `--profiles` compares whole named conditions and cannot be combined with `--vary`.

New manifests include a format-independent `document_sha256`. Composed validation checks task/answer/required identity invariance and hashes for shared documents; normal validation independently checks actual file bytes. Older environments remain runnable, but require regeneration for this new composed-content check.

## 3. Multiple models and 4. repeated trials

```powershell
fsbench run --envs envs/stress_v1 `
  --model openai/gpt-4o-mini --model PROVIDER/SECOND_MODEL --model PROVIDER/THIRD_MODEL `
  --arm files:naturalistic --arm indexed:naturalistic --arm indexed:index_first `
  --trials-per-cell 2 --interleave --order-seed 7 --temperature 0 --max-steps 40 `
  --experiment robustness_v1 --out runs/robustness_v1 --skip-existing
```

Replace the second and third model placeholders with models available through the configured provider. This produces 1,440 runs for 20 worlds and four profiles. It is a recipe, not a study already performed.

All trials use the same source environments, with isolated working copies for scratch writes. The scheduler shuffles conditions, models, policies, and trials within each world using a stable order seed. Interleaving is always on; `--interleave` is accepted for explicitness. `trial_index` starts at 1 and never changes environment seeds. The saved experiment plan includes all expected cells, execution order, settings, environment fingerprints, and a design ID. Resume rejects changed plans or input hashes. Do not reuse an output directory for changed settings. Legacy results remain evaluable; old saved plans are not rewritten into new designs.

`--provider openrouter` is the default and supports model slugs from different vendors. `--provider compatible` uses `FSBENCH_BASE_URL` and `FSBENCH_API_KEY` for another Chat Completions-compatible endpoint. Provider details stay in adapters. `fsbench.models.ModelAdapter.run(messages, tools, config)` returns `ModelResponse` with normalized text, tool calls, tokens, cost, latency, finish reason, and errors. Register a custom agent factory with `register_provider` for other protocols; custom adapters can reuse the existing agent loop. Missing provider usage or cost stays null, not zero. CLI model comparison uses one registered provider per invocation.

```powershell
fsbench evaluate --runs runs/robustness_v1 --paired --statistics --baseline clean `
  --bootstrap-seed 7 --out runs/robustness_v1/results.csv
fsbench plot --runs runs/robustness_v1 --paired --x condition --out runs/robustness_v1/plots
```

Pairing removes an entire world/task/layout seed tuple if any planned model × policy × condition × trial cell is missing, duplicated, or has a different input fingerprint for the same environment condition. Provider failures are recorded as outcomes, not silently dropped.

`statistics.json` and four CSV tables report cell means, stress-minus-clean robustness deltas, same-condition model/interface contrasts, descriptive variation, and two-factor endpoint differences of differences. Each metric keeps its own units. Paired standardized differences are reported only when the sample standard deviation is nonzero.

Repeated trials are averaged **within each world/cell before resampling worlds**, using 10,000 paired percentile bootstrap resamples and a stable seed. A metric missing from any trial in a cell is excluded for that world's metric comparison; each row reports its number of worlds. Within-seed variance measures repeated-trial variation; between-seed variance measures variation of world means; between-condition variance is descriptive variation of condition means. These are not fitted variance components.

Single-trial success rates use Wilson 95% intervals over independent worlds. Repeated-trial success uses world-bootstrap intervals. All-success bootstrap samples can produce a degenerate interval; the output marks boundary cases, which do not establish population certainty. Intervals are exploratory and unadjusted for multiple comparisons; no automatic significance wording is generated. Plots show world means with standard errors, not confidence intervals. `--interaction` remains the specialized 0-versus-.9 filename-noise report for one model/task/fixed configuration and now separates policies and averages repeated trials.

## 5. Trajectory and failure analysis

```powershell
fsbench inspect --run runs/robustness_v1/PATH_TO_RUN
fsbench compare-trace --runs runs/robustness_v1 --seed 7 --noise 0.9 `
  --model openai/gpt-4o-mini --trial-index 1
fsbench analyze-behavior --runs runs/robustness_v1 --paired `
  --group-by model filename_noise toolset tool_policy --out runs/robustness_v1/behavior.csv
```

`inspect --run` accepts a directory or an unambiguous folder name searched under `--runs` (default `runs`). Existing `inspect --env` behavior remains available. Full trajectories are also stored in re-evaluated `metrics.json`.

Labels include directory navigation, search, index search, required reads, distractors, stale/draft traps, near misses, duplicate reads, invalid paths, writes, and final answers. An action can have several labels; labels are derived from trace events and hidden evaluation metadata after the run, never exposed through agent tools.

* Search attempts include `find`, `glob`, `grep`, `search_files`, and `search_index`, including failed attempts. Before-evidence counters stop at the first required-document read.
* Distractor/stale counters count read occurrences before that first evidence, not unique paths. A stale/draft read is also a distractor read.
* `duplicate_read_count` counts re-reads of the same document identity, including another copy. A first read of a duplicate copy is labeled but is not itself a re-read.
* `backtrack_count` is a proxy: revisit a previously navigated directory after visiting another directory, with no new required document found since the earlier visit. It does not infer the agent's intentions.
* `answered_without_evidence` means a final answer was attempted before all required document identities were read. Search snippets alone do not count as full-document reads.
* `recovered_tool_error` means an erroneous tool action was followed by a successful tool action. It is separate from task success and the legacy trap-recovery metric.

For compatibility, `failure_type` retains legacy names such as `timeout`, `agent_error`, and `distractor_confusion`. `task_failure_type` adds `step_limit`, `provider_failure`, `near_miss_confusion`, `tool_misuse`, and `path_hallucination`, alongside retrieval, stale-version, reasoning, output-format, and required-tool failures. `failure_family=source_selection_failure` groups observed stale/near-miss answer matches. Exact decoy matching can identify source confusion even when required evidence was never read. These are deterministic diagnostic rules, not proof of a cognitive cause. Batch failure columns use the expanded classification.

## Validation and contributing

Run `python -m pytest`. Tests cover policy enforcement and dynamic schemas, invalid required-tool runs, composed content invariance, factorial generation, adapters and missing usage, multi-model/repeated scheduling and resume, complete-cell filtering, world-level statistics, factorial effects, trajectory labels, and the existing generator/index/evaluator behavior.

For contributions, start with a small failing fixture and a focused change. Include exact commands, seeds, provider/model settings, tool policy, trial count, and input fingerprints with experiment reports. Never commit `.env`, generated workspaces, or API keys. See the [README contribution steps](../README.md#help-out).
